### FakeModel

```ts
class FakeModel {
  constructor(replies?: (string | FakeReply)[], options?: { delayMs?: number; failFirst?: number; byTurn?: boolean; name?: string; });
}
```

A simulated model for tests: answers with the scripted replies in order (a
string is a text reply), then echoes. Never a network call.


The first n calls fail with `rate_limited` (transient), to test retries.

#### FakeModel.byTurn

```ts
readonly byTurn: boolean
```

Choose each reply by the conversation's turn (the first reply for a run's
first model call, the second for its second, then the last repeats)
instead of using replies up: one model serves many runs, also at once.

### KaggleOptions

```ts
interface KaggleOptions {
  apiToken?: string;
  proxyUrl?: string;
  proxyToken?: string;
  /** Where proxy tokens are minted (tests). */
  apiBase?: string;
}
```

Kaggle's Model Proxy: the hosted models your Kaggle account's
AI-model allowance pays for. Credentials, in order: `apiToken`; `proxyUrl`

KAGGLE_API_TOKEN, or the `access_token` file in KAGGLE_CONFIG_DIR or
~/.kaggle. The engine mints the short-lived proxy token and renews it.
For prototypes and tests, not production traffic.

### AzureOptions

```ts
interface AzureOptions {
  endpoint?: string;
  apiKey?: string;
  token?: string;
  tenantId?: string;
  clientId?: string;
  clientSecret?: string;
  managedIdentity?: boolean;
  api?: "responses" | "chat";
  scope?: string;
  /** Where Entra ID tokens are issued (sovereign clouds; tests). */
  authority?: string;
  /** Another managed-identity endpoint (tests). */
  identityEndpoint?: string;
}
```

Azure OpenAI or Microsoft Foundry. `endpoint` is the
resource name or URL (else AZURE_OPENAI_ENDPOINT). Credentials, in order:
`apiKey`; `token` (a bearer token from elsewhere); `clientSecret` with
`tenantId` and `clientId` (a service principal); `managedIdentity` (with
`clientId` for a user-assigned identity); else AZURE_OPENAI_API_KEY, or
AZURE_TENANT_ID + AZURE_CLIENT_ID + AZURE_CLIENT_SECRET, or
AZURE_USE_MANAGED_IDENTITY=1. The engine obtains and renews Entra ID
tokens. `api: "chat"` for Foundry's models from other makers.

### BedrockOptions

```ts
interface BedrockOptions {
  region?: string;
  apiKey?: string;
  api?: "auto" | "messages" | "chat" | "responses";
  baseUrl?: string;
}
```

Amazon Bedrock with an API key. `region` (else AWS_REGION
or AWS_DEFAULT_REGION; there is no default, so data never goes to a region
you did not choose); `apiKey` (else AWS_BEARER_TOKEN_BEDROCK). Claude is
called over the Anthropic Messages API and other makers' models over Chat
Completions; `api` forces one. `baseUrl` reaches bedrock-mantle or a VPC
endpoint. IAM roles (SigV4) are not supported yet.

### VertexOptions

```ts
interface VertexOptions {
  project?: string;
  location?: string;
  token?: string;
  credentialsFile?: string;
  api?: "auto" | "chat" | "claude";
  /** Another API host (a private endpoint; tests). */
```

Google Vertex AI. `project` (else GOOGLE_CLOUD_PROJECT) and

### ModelAnswer

```ts
type ModelAnswer = string | FakeReply | { message: Record<string, unknown> } | { error: { kind: string; message: string } };
```

A model function's answer: text, tool calls (`FakeReply.toolCall`), an
exact assistant message, or a classified error (`\{ error: \{ kind:
"rate_limited", message \} \}` is retried as a provider's would be).

### FunctionModel

```ts
class FunctionModel {
  constructor(respond: (call: ModelCall) => ModelAnswer | Promise<ModelAnswer>, options?: { name?: string; });
}
```

A model written in JavaScript: for each model call the
engine calls `respond` with the request, and the agent loop (tools,
approvals, retries, limits) goes on with its answer. For a model that runs
in the page (WebGPU, a browser's built-in model), your own client, or
scripted replies chosen by what the request says (tests and demos, where
several agents share one model). If `respond` throws, the call fails with
`model_failed`.

### Gateway

```ts
class Gateway {
  constructor(options?: GatewayOptions);
}
```

Model calls without an agent: `chat`, `stream` and `embed`, with the agent's retries and fallback models.

#### Gateway.chat

```ts
chat<Output = unknown>(model: Model, input: ChatInput, options?: ChatOptions): Promise<ChatReply<Output>>
```

One answer.

#### Gateway.stream

```ts
stream<Output = unknown>(model: Model, input: ChatInput, options?: ChatOptions): ChatStream<Output>
```

The answer as it is written: `for await (const chunk of gw.stream(…))`.

#### Gateway.embed

```ts
embed(embedder: Embedder, texts: string[], options?: { signal?: any; }): Promise<number[][]>
```

One vector per text, in order.

### ChatInput

```ts
type ChatInput = string | Record<string, unknown>[];
```

Text, or messages (the transcript format of `result.messages`; `content` may be a string).

### ChatOptions

```ts
interface ChatOptions {
  /** The system message. */
  instructions?: string;
  temperature?: number;
  maxTokens?: number;
  /** A JSON Schema the answer must match; `reply.output` is then the parsed JSON. */
  output?: Record<string, unknown>;
  /**
   * Tools the model may call (tool specs, as a FunctionModel's `call.tools`):
   * the reply's `message` then holds its tool calls, for you to run. With
   * this, a FunctionModel can pass an agent's request on to a real model.
   */
  tools?: Record<string, unknown>[];
  /** Aborting cancels the call (the HTTP request stops). */
  signal?: AbortSignal;
}
```

### ChatReply

```ts
interface ChatReply<Output = unknown> {
  /** All text of the answer. */
  text: string;
  /** The assistant message. */
  message: Record<string, unknown>;
  usage: Record<string, number>;
  /** Why the model stopped, e.g. "stop" or "length". */
  stopReason: string | null;
  /** "provider:model" that answered (a fallback, if the first failed). */
  model: string;
  /** The parsed JSON answer, with `output`. */
  output: Output | null;
}
```

A model's answer.

### Chunk

```ts
interface Chunk {
  type: "text" | "restart";
  text: string;
}
```

A piece of a streamed answer. `restart`: a retry started the answer over, so drop the text shown so far.

### GatewayOptions

```ts
interface GatewayOptions {
  /** Models tried in order when the one asked for fails with a transient error (after its retries). */
  fallbacks?: Model[];
  /** Other error kinds that also move on, e.g. "context_overflow". */
  fallbackOn?: string[];
  /** How transient errors are retried (default: 3 attempts, backoff from 0.5 s). */
  retry?: Retry;
  /** The longest Retry-After that is waited for, in seconds (default 60). */
  maxRetryAfterSecs?: number;
}
```

### ChatStream

```ts
class ChatStream<Output = unknown> implements AsyncIterable<Chunk> {
  constructor(nativeStream: NativeChatStream);
}
```

A streamed answer: `for await (const chunk of stream)`, then `await stream.reply()`. Leaving the loop early cancels the call.

#### ChatStream.reply

```ts
reply(): Promise<ChatReply<Output>>
```

Waits for the call; the whole answer.

#### ChatStream.cancel

```ts
cancel(): void
```

Cancels the call.

### parseEnv

```ts
function parseEnv(text: string): Record<string, string>
```

Parse .env text: NAME=value lines, `export NAME=value`, # comments, and
values in single or double quotes. No variable expansion. A malformed line
throws an Error naming the line number (never its content: it may be a secret).

### LoadEnvOptions

```ts
interface LoadEnvOptions {
  /** Replace variables that are already set (default: keep them). */
  override?: boolean;
  /** Throw if the file is missing (default: a missing file is fine). */
  required?: boolean;
}
```

### loadEnv

```ts
function loadEnv(path?: string, options?: LoadEnvOptions): string[]
```

Read a .env file into process.env and return the NAMES it set (sorted;
never the values). Files over 1 MB are refused. Keep the file out of git.

### envStatus

```ts
function envStatus(): Record<string, boolean>
```

Which providers have a key right now: \{ openai: true, gemini: false, ... \}. Names and yes/no only.

### keyName
