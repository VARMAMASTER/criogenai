## openai

```ts
function openai(model: string, options?: ModelOptions): ProviderModel
```

A model on OpenAI's API (OPENAI_API_KEY), e.g. openai("gpt-5-mini"). The same as the string "openai:gpt-5-mini".

**Parameters**

- `model` (`string`): The model name, e.g. "gpt-5-mini".
- `options` (`ModelOptions`, optional): `apiKey` (else OPENAI_API_KEY) and `baseUrl`.

**Raises**

- `Error`: No key given and OPENAI_API_KEY is not set.

**Example**

```ts
import { Agent, openai } from "criogen";

const agent = new Agent({ model: openai("gpt-5-mini"), instructions: "Answer in one sentence." });
```

## FakeModel

```ts
class FakeModel {
  constructor(replies?: (string | FakeReply)[], options?: { delayMs?: number; failFirst?: number; byTurn?: boolean; name?: string; });
}
```

A simulated model for tests: answers with the scripted replies in order (a
string is a text reply), then echoes. Never a network call.

Use it in tests and examples: script text answers and tool calls
(`FakeReply.toolCall`), and the agent loop runs for real around them.
Usage is counted, and replies name the model "fake".

**Parameters**

- `replies` (`(string | FakeReply)[]`, default `[]`): The answers, in order: a string is a text reply; `FakeReply.toolCall(...)` and `FakeReply.toolCalls(...)` ask for tools.
- `options` (`{ delayMs?: number; failFirst?: number; byTurn?: boolean; name?: string; }`, default `{}`): `delayMs` (default 0), `failFirst` (default 0), `byTurn` (default false) and `name`, as described on the properties.

**Example**

```ts
import { Agent, FakeModel, FakeReply } from "criogen";

const model = new FakeModel([FakeReply.toolCall("lookup", { orderId: "A-1" }), "Order A-1 shipped."]);
// A model that fails twice with rate_limited, then answers: tests retries.
const flaky = new FakeModel(["Done."], { failFirst: 2 });
console.log((await new Agent({ model: flaky }).run("Go")).text); // "Done."
```

### FakeModel.replies

```ts
readonly replies: FakeReply[]
```

The scripted replies, in order.

### FakeModel.delayMs

```ts
readonly delayMs: number
```

How long each reply takes, in milliseconds.

### FakeModel.failFirst

```ts
readonly failFirst: number
```

The first n calls fail with `rate_limited` (transient), to test retries.

### FakeModel.byTurn

```ts
readonly byTurn: boolean
```

Choose each reply by the conversation's turn (the first reply for a run's
first model call, the second for its second, then the last repeats)
instead of using replies up: one model serves many runs, also at once.

### FakeModel.name

```ts
readonly name: string | undefined
```

The model name in replies ("fake:&lt;name>"), to tell two fake models apart.


## openaiCompatible

```ts
function openaiCompatible(model: string, options: ModelOptions & { baseUrl: string; name?: string; allowInsecureHttp?: boolean; }): ProviderModel
```

Any OpenAI-compatible server. `allowInsecureHttp`: send the key over plain
`http://` to another machine (a vLLM server on your LAN); refused by
default, because a key sent over http is readable by anyone on the path.

**Parameters**

- `model` (`string`): The model name the server expects.
- `options` (`ModelOptions & { baseUrl: string; name?: string; allowInsecureHttp?: boolean; }`): `baseUrl` (required: the API root, usually ending in /v1), `apiKey` if the server wants one, `name` (shown as the provider; default "custom") and `allowInsecureHttp`.

**Example**

```ts
import { Agent, openaiCompatible } from "criogen";

const agent = new Agent({
  model: openaiCompatible("meta-llama/Llama-3.3-70B-Instruct", { baseUrl: "http://localhost:8000/v1", name: "vllm" }),
});
```

## ModelOptions

```ts
interface ModelOptions {
  apiKey?: string;
  baseUrl?: string;
}
```

Options of the provider functions (`openai`, `anthropic`, `gemini`, ...).

**Fields**

- `apiKey` (`string`, optional): The API key. Without it, the key comes from the provider's environment variable (e.g. OPENAI_API_KEY).
- `baseUrl` (`string`, optional): Another address for the provider's API (a proxy, a regional endpoint). Without it, the provider's own.

## ProviderModel

```ts
class ProviderModel {
  constructor(kind: string, model: string, options?: ModelOptions & { name?: string; allowInsecureHttp?: boolean; });
}
```

A model on a provider's API. The provider functions (`openai("...")`,
`anthropic("...")`, ...) make these; construct one directly only for a
provider name held in a variable.

The API key is kept private: it is not a property, and `toJSON()` (so
`JSON.stringify`) leaves it out.

**Parameters**

- `kind` (`string`): The provider name (as in "provider:model" strings), "openai_compatible" or "anthropic_compatible".
- `model` (`string`): The model name, as the provider knows it.
- `options` (`ModelOptions & { name?: string; allowInsecureHttp?: boolean; }`, default `{}`): `apiKey` and `baseUrl`; for the compatible kinds also `name` (shown as the provider) and `allowInsecureHttp`.

**Raises**

- `ValidationError`: The provider needs a key, none was given or found in its environment variable, and there is no `baseUrl` (`invalid_value`).

## KaggleOptions

```ts
interface KaggleOptions {
  apiToken?: string;
  proxyUrl?: string;
  proxyToken?: string;
  apiBase?: string;
}
```

Options of `kaggle(...)` and `KaggleModel`.

Kaggle's Model Proxy serves the hosted models your Kaggle account's
AI-model allowance pays for. Credentials, in order: `apiToken`; `proxyUrl`
and `proxyToken`; else MODEL_PROXY_URL and MODEL_PROXY_API_KEY,
KAGGLE_API_TOKEN, or the `access_token` file in KAGGLE_CONFIG_DIR or
~/.kaggle. The engine mints the short-lived proxy token and renews it.
For prototypes and tests, not production traffic.

**Fields**

- `apiToken` (`string`, optional): A Kaggle API token; the engine mints the proxy token from it. Else the environment (see above).
- `proxyUrl` (`string`, optional): The proxy's address, with `proxyToken` (a proxy token you already have).
- `proxyToken` (`string`, optional): A proxy token minted elsewhere, with `proxyUrl`. It is not renewed.
- `apiBase` (`string`, optional): Where proxy tokens are minted (tests).

## AzureOptions

```ts
interface AzureOptions {
  endpoint?: string;
  apiKey?: string;
  token?: string;
  tenantId?: string;
  clientId?: string;
  clientSecret?: string;
  managedIdentity?: boolean;
  api?: "responses" | "chat";
  scope?: string;
  authority?: string;
  identityEndpoint?: string;
}
```

Options of `azure(...)` and `AzureModel`: the endpoint and credentials.

For Azure OpenAI or Microsoft Foundry. `endpoint` is the
resource name or URL (else AZURE_OPENAI_ENDPOINT). Credentials, in order:
`apiKey`; `token` (a bearer token from elsewhere); `clientSecret` with
`tenantId` and `clientId` (a service principal); `managedIdentity` (with
`clientId` for a user-assigned identity); else AZURE_OPENAI_API_KEY, or
AZURE_TENANT_ID + AZURE_CLIENT_ID + AZURE_CLIENT_SECRET, or
AZURE_USE_MANAGED_IDENTITY=1. The engine obtains and renews Entra ID
tokens. `api: "chat"` for Foundry's models from other makers.

**Fields**

- `endpoint` (`string`, optional): The resource name ("my-resource") or its URL. Else AZURE_OPENAI_ENDPOINT.
- `apiKey` (`string`, optional): An Azure OpenAI API key. Else AZURE_OPENAI_API_KEY, unless another credential is given.
- `token` (`string`, optional): A bearer token you obtained yourself (it is not renewed).
- `tenantId` (`string`, optional): The Entra ID tenant, with `clientId` and `clientSecret`. Else AZURE_TENANT_ID.
- `clientId` (`string`, optional): The service principal's application id; with `managedIdentity`, a user-assigned identity. Else AZURE_CLIENT_ID (for a client secret).
- `clientSecret` (`string`, optional): A service principal's secret, with `tenantId` and `clientId`.
- `managedIdentity` (`boolean`, optional): `true`: use the managed identity of the Azure host the code runs on.
- `api` (`"responses" | "chat"`, optional): "responses" (OpenAI's models, the default) or "chat" (Chat Completions, for Foundry's models from other makers).
- `scope` (`string`, default `"https://cognitiveservices.azure.com/.default"`): The scope Entra ID tokens are requested for. Foundry also accepts "https://ai.azure.com/.default".
- `authority` (`string`, optional): Where Entra ID tokens are issued (sovereign clouds; tests).
- `identityEndpoint` (`string`, optional): Another managed-identity endpoint (tests).

## AzureModel

```ts
class AzureModel {
  constructor(model: string, options?: AzureOptions);
}
```

A deployment on Azure OpenAI or Microsoft Foundry. `azure(model, options)`
and the string "azure:&lt;deployment>" make the same thing; see `AzureOptions`
for the endpoint and credentials. Secrets are not properties, and
`toJSON()` leaves them out.

Needs the 0.1.6 engine for your platform; with an older one, using the
model (building an agent with it, a gateway call) throws an error with
code `unsupported`.

**Parameters**

- `options` (`AzureOptions`, default `{}`): The endpoint, credentials and API (see `AzureOptions`); without them, the environment.

**Raises**

- `TypeError`: `api` is not "responses" or "chat".

**Example**

```ts
import { Agent, AzureModel } from "criogen";

// A service principal; the engine fetches and renews Entra ID tokens.
const model = new AzureModel("gpt-5-mini", {
  endpoint: "my-resource",
  tenantId: process.env.AZURE_TENANT_ID,
  clientId: process.env.AZURE_CLIENT_ID,
  clientSecret: process.env.AZURE_CLIENT_SECRET,
});
const agent = new Agent({ model });
```

## BedrockOptions

```ts
interface BedrockOptions {
  region?: string;
  apiKey?: string;
  api?: "auto" | "messages" | "chat" | "responses";
  baseUrl?: string;
}
```

Options of `bedrock(...)` and `BedrockModel`: region, key and API.

Amazon Bedrock with an API key. `region` (else AWS_REGION
or AWS_DEFAULT_REGION; there is no default, so data never goes to a region
you did not choose); `apiKey` (else AWS_BEARER_TOKEN_BEDROCK). Claude is
called over the Anthropic Messages API and other makers' models over Chat
Completions; `api` forces one. `baseUrl` reaches bedrock-mantle or a VPC
endpoint. IAM roles (SigV4) are not supported yet.

**Fields**

- `region` (`string`, optional): The AWS region, e.g. "us-east-1". Else AWS_REGION or AWS_DEFAULT_REGION; there is no default.
- `apiKey` (`string`, optional): A Bedrock API key. Else AWS_BEARER_TOKEN_BEDROCK.
- `api` (`"responses" | "chat" | "auto" | "messages"`, default `"auto"`): Which API to call: "auto" (Anthropic's models over the Messages API,
  the rest over Chat Completions), "messages", "chat" or "responses" (for
  models whose model card lists the Responses API).
- `baseUrl` (`string`, optional): Another endpoint: bedrock-mantle or a VPC endpoint.

## VertexOptions

```ts
interface VertexOptions {
  project?: string;
  location?: string;
  token?: string;
  credentialsFile?: string;
  api?: "auto" | "chat" | "claude";
  host?: string;
  tokenUrl?: string;
  metadataUrl?: string;
}
```

Options of `vertex(...)` and `VertexModel`: project, location and credentials.

Google Vertex AI. `project` (else GOOGLE_CLOUD_PROJECT) and

GOOGLE_APPLICATION_CREDENTIALS, gcloud's application-default file, or the

**Fields**

- `location` (`string`, optional): The region, e.g. "us-central1" or "global"; it decides where data is processed. Else GOOGLE_CLOUD_LOCATION; there is no default.
- `token` (`string`, optional): An OAuth access token you obtained yourself.
- `credentialsFile` (`string`, optional): A credentials file of type `authorized_user` (as `gcloud auth application-default login` writes); service-account key files are refused. Else GOOGLE_APPLICATION_CREDENTIALS, gcloud's file, or the metadata server.
- `api` (`"chat" | "auto" | "claude"`, default `"auto"`): Which endpoint to call: "auto" (`claude-…` models to Claude's endpoint,
  the rest to the OpenAI-compatible one), "chat" (OpenAI-compatible Chat
  Completions) or "claude" (Anthropic Messages).
- `host` (`string`, optional): Another API host (a private endpoint; tests).
- `tokenUrl` (`string`, optional): Token endpoints elsewhere (tests).
- `metadataUrl` (`string`, optional): Another metadata server address (tests).

## ModelCall

```ts
interface ModelCall {
  messages: Record<string, unknown>[];
  tools?: Record<string, unknown>[];
  settings?: Record<string, unknown>;
  output?: Record<string, unknown> | null;
  [key: string]: unknown;
}
```

What a model function receives: the request the engine would send to a provider.

It has the messages so far, the tools the model may call, the settings
and any output schema (`ModelRequest` in schemas/criogen.schema.json).

**Fields**

- `messages` (`Record<string, unknown>[]`): The conversation so far, system message first, in the transcript format of `result.messages`.
- `tools` (`Record<string, unknown>[]`, optional): The tools the model may call, each with `name`, `description` and `input_schema`.
- `settings` (`Record<string, unknown>`, optional): Generation settings, such as temperature and the token limit, when set.
- `output` (`Record<string, unknown> | null`, optional): A structured-output request (`{ schema, strategy? }`: the JSON Schema
  the answer must match), when there is one. An agent's `output` schema
  reaches a function model as a `final_output` tool in `tools` instead.

## ModelAnswer

```ts

```

A model function's answer.

## FunctionModel

```ts
class FunctionModel {
  constructor(respond: (call: ModelCall) => ModelAnswer | Promise<ModelAnswer>, options?: { name?: string; });
}
```

A model written in JavaScript: for each model call the
engine calls `respond` with the request, and the agent loop (tools,
approvals, retries, limits) goes on with its answer. For a model that runs
in the page (WebGPU, a browser's built-in model), your own client, or
scripted replies chosen by what the request says (tests and demos, where
several agents share one model). If `respond` throws, the call fails with
`model_failed`.

Needs the 0.1.4 engine or newer for your platform; with an older one,
using the model throws an error with code `unsupported`.

**Parameters**

- `respond` (`(call: ModelCall) => ModelAnswer | Promise<ModelAnswer>`): Called for every model call with the request; returns (or resolves to) the answer: text, `FakeReply.toolCall(...)`, `{ message }` or `{ error: { kind, message } }`.
- `options` (`{ name?: string; }`, default `{}`): `name`: the model name in replies and traces (default "function").

**Raises**

- `TypeError`: `respond` is not a function.

**Example**

```ts
import { Agent, FakeReply, FunctionModel } from "criogen";

// Ask for the weather tool once, then answer with what it returned.
const model = new FunctionModel((call) => {
  const last = call.messages[call.messages.length - 1];
  if (last.role === "user") return FakeReply.toolCall("get_weather", { city: "Paris" });
  return `The tool said: ${JSON.stringify(last.content)}`;
});
const agent = new Agent({ model });
```


The model name in replies and traces.
