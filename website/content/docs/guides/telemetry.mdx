title: "Tracing: Langfuse and OpenTelemetry"
description: Every run as a trace, with model calls as generations; content capture can be turned off.
---


Every run becomes a trace: workflow nodes are spans, model calls are
*generations* (model, input, output, tokens), tool calls are tool
observations, failures are marked as errors. Export goes over OTLP/HTTP to
Langfuse or any OpenTelemetry collector.

## See runs on your own computer

The **local trace viewer** shows every run on a page, with no account and
nothing leaving the computer: model calls, tool calls and steps on a time
axis, durations, tokens, cost (from your prices), failures, and where the
time went (model, tools, CriogenAI and your code).

<Sample name="telemetry" region="local" />

- Start it with `python -m criogenai.trace`, `npx criogenai trace` or the
  `criogenai-trace` binary, and open `http://127.0.0.1:4318`. Runs are kept in
  `~/.criogen/traces.db` (`--memory` for none): the newest 10 000, for 14
  days.
- Prompts and outputs appear only with content capture on; otherwise you see
  structure, timing, tokens and error codes.
- **Cost**: pass `--prices prices.json` (USD per million tokens by
  `provider:model` or model name, e.g. `{"gpt-5-mini": {"input": 0.25,
  "output": 2}}`). CriogenAI ships no price list: a stale price is worse than
  none.
- It listens on `127.0.0.1` only. To share one on a network, pass
  `--allow-remote --token-env NAME`; clients then send that token.
- It is an ordinary OTLP/HTTP (JSON) receiver, so the same runs can also go
  to Langfuse: give an agent one exporter, or run the viewer while you
  develop and Langfuse in production.

- **Never slows or breaks a run**: the observer only queues events; a
  background task batches and sends them, and retries on transient errors.
- **Sensitive data**: in every language, prompts, answers, tool data,
  **error messages** (they echo what failed) and the run's `user_id`,
  `session_id` and custom metadata stay out of traces unless you set
  `capture_content=True` / `captureContent: true` / `.capture_content(true)`.
  Structure, timing, usage, status and error **codes** always go. A `mask`
  function redacts what is exported when capture is on.
- **Metadata**: `name`, `release`, `environment` and `tags` are always
  attached to the trace; `user_id`, `session_id` and any other JSON only
  with content capture on.
