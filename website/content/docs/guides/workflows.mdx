A **workflow** is a graph of steps (nodes) over a shared state. Each node
reads the state and returns the keys it changes. The engine runs ready
nodes [in steps](/docs/concepts/runs/), concurrently, and checks the graph
before the first run.

## Building blocks

| Piece | Use |
|---|---|
| **Edge** | After A, run B (or `END`) |
| **Router** | After A, a function of the state picks the next node by label |
| **Parallel nodes** | Several edges from one node: they run at the same time |
| **Join** | Run a node once all of its sources have finished |
| **Goto** | A node chooses its next nodes itself (declared ahead) |
| **Reducer** | How parallel writes to one key combine: replace, append, update by id |
| **Suspend** | A node pauses the run for a person; `resume` gives it the answer |
| **Policies** | A deadline and a step limit per run; per-node timeouts and retries with backoff (Rust) |
| **Agents as nodes** | An agent can be one node of a workflow: `wf.add_node(name, agent)`, `.addNode(name, agent)`, `agent.as_node()` |

## Durable workflows

A workflow compiled with storage gives threads (`app.thread(id)` in
Python and TypeScript, `storage.workflow_thread(&workflow, id)` in Rust)
the same guarantees as agents: progress saved every step, a pause that waits in the
database and is answered from any process, `retry()` after a failure
without re-running finished nodes, history, rewind and the audit trail.
