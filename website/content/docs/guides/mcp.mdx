The **Model Context Protocol** is how tool servers are shared. CriogenAI's MCP
client gives an agent the tools of any MCP server: a process your app starts
(**stdio**) or a server at a URL (**Streamable HTTP**). The client runs in the
Rust engine, so it behaves the same in every language.

## Use a server

<Sample name="mcp" />

- Pass a **server** to `tools` for all its tools, or pick some with
  `server.tool(name)` (Rust: `.only([...])` before `connect`).
- **`prefix`** keeps two servers apart: the agent sees `files_read_file`.
  Names are also mapped to what model APIs accept (`.` becomes `_`, at most
  64 characters); the server still gets its own name. Two tools that would
  map to the same name fail with `mcp_tool_name`.
- MCP tools are ordinary tools: they work with
  [approvals](/docs/guides/approvals/), timeouts, limits, hooks, streaming
  and the audit trail.
- A stdio server inherits your environment plus `env`. If it exits, the next
  call starts it again. `close()` stops it (stdin closed, killed after 2 s).
- In the browser (`criogenai/web`), `mcp.http` works; `mcp.stdio` throws
  `unsupported`.

## Call a tool yourself

<Sample name="mcp" region="direct" only={["python", "typescript"]} />

A call returns the tool's text, its JSON value (`structuredContent`), or its
content blocks. A tool that reports a failure (`isError`) raises a
`ToolError` with its message: inside an agent, the model sees it and can try
again.

## What a server can and cannot do

The client **uses tools only**. A server cannot sample your model, read your
files or ask your users anything through CriogenAI. What it says is data:

- Its behaviour hints decide nothing by default. `destructiveHint` is kept
  (it only makes CriogenAI more careful); `readOnlyHint` and `idempotentHint`
  would make failed calls retried, so they count only with
  `trust_annotations` / `trustAnnotations`.
- Every message read is limited in size (4 MiB by default), every call in
  time (60 s), the number of tools (1 000) and the depth and size of their
  schemas are capped, and descriptions are cut to 8 000 characters.
- Header and environment values (tokens) never appear in an error, a log or
  a `repr`. Headers go over `https`, or plain `http` only to this computer.

## Versions

CriogenAI speaks MCP **2026-07-28** (stateless, `server/discover`) and falls
back to the `initialize` handshake for servers from 2025-11-25 and earlier,
so current and older servers both work. Not supported yet: resources,
prompts, sampling, elicitation, OAuth sign-in (pass a token in a header),
and serving your own tools as an MCP server.

## Errors

| Code | When |
|---|---|
| `mcp_connect` | The server could not be started or reached, or refused the credentials. |
| `mcp_protocol` | It answered something the client cannot use, or a version CriogenAI does not speak. |
| `mcp_tool_name` | Two of its tools map to the same name: set a `prefix` or leave one out. |
| `mcp_tool_schema` | A tool's input schema is not an object schema, or is too large or deep. |
| `mcp_timeout` | It was not ready within the connect timeout (30 s). |
| `mcp_closed` | It stopped, or the server object was closed. |
