## What every model gets

- **Streaming**, assembled into one message the same way for every
  provider.
- **Classified errors**: `rate_limited`, `overloaded`, `context_overflow`,
  `auth`, … ([all codes](/docs/reference/errors/)). Retries honour
  `Retry-After`; requests that never left are retried at once.
- **Fallback**: rate limits, overload and outages move to the next model
  (`fallbacks`); other error kinds can too (`fallback_on` /
  `fallbackOn`, e.g. `context_overflow` to a model with a longer context).
- **Retries**: `model_retry` / `modelRetry` (attempts and backoff), and
  `tool_retry` / `toolRetry` for tools marked read-only or idempotent.
- **Keys stay secret**: removed from every error message and from `Debug`
  output; never sent to another host (redirects are not followed).
- **Bounded**: a response larger than 64 MiB fails instead of filling memory.

For self-hosted models nothing leaves your network, which is often the
simplest answer for patient data.

## Call a model directly

For one call without an agent (summarize, classify, draft, embed), use
`Gateway`: `chat` returns the answer, `stream` yields it as it is
written, `embed` turns texts into vectors. Retries and fallback models
work as for an agent, and `reply.model` names the model that answered.
With `output` (a JSON Schema) the answer is JSON, parsed and checked
against the schema. A stream that a retry starts over yields a `restart`
chunk, so a UI can drop the text it showed. `Gateway` runs in your
process; the [gateway server](/docs/guides/gateway/) is a separate
program.
