The TypeScript package also runs **in the browser**: the same Rust engine,
compiled to WebAssembly, behind the same API. Agents, tools, approvals,
typed output, threads, workflows and the gateway work as on a server; the
agent loop runs in the visitor's tab (or a Web Worker), so a run costs your
servers nothing. The [playground](/playground/) runs its code samples this way.

## Keys and providers

A browser has no environment variables: pass `apiKey`. **A key in a page is
visible to whoever uses the page.** That is fine for a person's own key in
their own tab (the playground does this: the key goes from the tab to the
provider and nowhere else). In a product, do not ship your key: point the
model at your own server, or at a [CriogenAI gateway](/docs/guides/gateway/)
with a virtual key per user and its limits.

The provider must accept calls from a browser page (CORS). OpenAI, Anthropic
(CriogenAI adds the header Anthropic asks browser callers for), Gemini's
OpenAI-compatible endpoint and OpenRouter do; a local Ollama needs
`OLLAMA_ORIGINS`. When a call is refused, the error says it may be CORS. The
usual rules still hold: redirects are never followed, a key never goes over
plain `http` to another machine, a response over 64 MiB is refused, and a
cancelled run stops its download.

## Models written in JavaScript

`FunctionModel` is a model whose every call goes to a function: a model
running in the page (WebGPU, a browser's built-in model), your own client, or
scripted replies chosen by what the request says. It works on servers too.

## What needs a server

These fail with the error code `unsupported` in the browser:

- **Databases.** Storage is in the tab's memory: a thread lasts as long as
  the page. SQLite and Postgres, encryption at rest and durable audit
  trails need a server.
- **Telemetry export** (Langfuse, OpenTelemetry) and the **web tools**
  (search, reading pages).

## Good to know

- **One thread.** Tasks are concurrent, not parallel: model and tool calls
  overlap (they mostly wait), heavy computation does not spread over cores.
- **Background tabs.** Browsers slow timers in background tabs, and phones
  may pause them: short, interactive runs fit best. Long or durable runs
  belong on a server.
- **Speed.** CriogenAI's own work is a fraction of a millisecond per run on a
  server, and a model call takes seconds; WebAssembly is somewhat slower
  than native, which matters little next to the model. What a visitor can
  feel is the network: each model call travels from their connection.
- **Tested** in Chromium, Firefox and WebKit (Safari's engine), and with the
  same test suite as the Node package.
